# 交互回归防护

本文件记录已出现过的问题及其防护规则。修改样式、手势、状态同步或缓存时，应检查对应入口和异常路径，不能仅凭静态截图或面板最终关闭来判断交互正常。

## 已知问题与防护规则

| 场景 | 根因与影响 | 防护规则 | 回归覆盖 |
| --- | --- | --- | --- |
| 播放页下拉滞后、松手后直接消失 | 样式合并改变规则顺序，同等优先级的基础规则覆盖拖动时的 `transition: none` 和收起时的 `transform`。拖动仍有 0.3 秒缓动，收起没有完整位移动画。 | 打开、拖动、关闭状态使用明确的组合选择器，例如 `body.mobile-player-open.mobile-player-dragging .player`。手指接触并拖动期间不启用位移缓动；松手后才执行回弹或收起动画。 | 浏览器逐步测量拖动 30px、80px 时的面板位移与计算样式，并检查松手后的中间帧。 |
| 手指回拉到起点附近，面板仍停在旧位置 | 手势已经开始后，仍使用最初的 5px 启动阈值过滤后续移动。 | 区分手势识别阶段与持续拖动阶段。识别后持续跟随，允许回到 0px；向上越过起点时钳制到 0px。 | 检查 80px → 2px → 负位移 → 再次下拉，以及取消和短距离回弹。 |
| 合并样式后滑轨消失 | 将 WebKit 与 Firefox 专用伪元素放入同一选择器列表，浏览器可能丢弃整条规则。 | 专用伪元素保留独立规则；声明相同不代表可以合并选择器。 | 资源测试检查选择器，浏览器测试检查滑轨实际绘制的像素。 |
| 输入时间或键盘收起时误关闭弹框 | 聚焦、失焦改变弹框位置；只按松手坐标判断外部点击，会把内部操作识别为关闭。 | 编辑布局保持到弹框关闭；外部关闭同时检查按下与松开位置，取消手势不得关闭。 | 时间与分钟输入、焦点变化、布局移动、内部按下后外部松开、嵌套弹框。 |
| 关闭嵌套菜单后残留蓝框或触摸高亮 | 焦点恢复与触摸产生的 hover/focus 状态混用。 | 触摸和鼠标打开弹框时控制初始焦点外观，保留键盘 `:focus-visible`；hover 装饰按输入能力区分。 | 队列菜单外部关闭、共享关闭按钮、键盘焦点与触摸后的计算样式。 |
| 旧响应覆盖新操作或新房间 | 请求结束时未检查房间、账号、操作或菜单代次；旧请求的清理逻辑释放了新请求的忙碌状态。 | 成功、失败和 `finally` 都检查所属上下文；忙碌状态只能由持有它的请求释放。新菜单打开时使旧操作失效。 | 状态、导入查询、加入队列、编辑队列、账号搜索的延迟响应与失败恢复。 |
| 切换歌单沿用旧位置，后台更新干扰其他页面 | 未区分首次打开、已有浏览记录和隐藏列表，直接使用当前窗口位置恢复歌单。 | 新歌单无记录时从顶部开始；记录按账号和歌单隔离。隐藏列表只保留恢复目标，回到列表后再恢复；过期恢复不能释放新恢复任务的保护状态。 | 切换、刷新、深列表、最近播放、完整播放页、恢复中断及连续恢复。 |
| 中文选词时提前搜索，失败后无法直接继续 | 普通输入和确认键未区分输入法合成状态；失败清空了上下文或分页状态。 | 合成结束后再搜索；确认键忽略 `isComposing` 和兼容键码。首次失败提供重试，分页失败保留已有结果并重试同一页。 | 合成事件顺序、查询缓存、账号隔离、首屏重试与分页重试。 |
| 播放按钮、进度和实际状态短时不一致 | 旧轮询覆盖预期状态，或者过早把命令响应当作播放已确认。 | 立即同步预期按钮与进度，以音箱状态确认结束操作；失败恢复只作用于当前操作。连接中断时冻结进度，首次连接失败避免每次轮询重复弹提示。 | 播放、暂停、切歌、拖动进度、乱序响应、断线与恢复。 |
| 音量误触跳升 | 点击远处滑轨直接映射为大幅音量变化。 | 保留滑轨误触保护、向上拖动限幅和微调按钮；取消、失去指针捕获与切换房间均须结束旧手势。 | 音量拖动、远端点击、取消、分组及跨房间写入。 |

## 验证要求

- 样式重构同时验证正常动效和减少动态效果，不能只在关闭动画时验证手势。
- 手势测试检查即时位移、回拉、取消、短距离回弹和松手后的中间帧。只检查最终关闭状态会漏掉拖动延迟和动画丢失。
- 同一行为覆盖主播放页、迷你播放条、队列及二级菜单等相关入口。
- 并发测试应包含旧请求先完成、后完成和失败三种顺序，并检查提示、按钮和忙碌状态。
- Chromium 与 WebKit 的手机尺寸模拟不能替代真实 iPhone Safari 的输入法、原生选择器和浏览器工具栏验证。

## 测试入口

```sh
npm --prefix web test
npm --prefix web run test:ui
UI_TEST_BROWSER=webkit npm --prefix web run test:ui
```

聚焦播放页拖动回归：

```sh
UI_TEST_PLAYER_GESTURE_ONLY=1 npm --prefix web run test:ui
UI_TEST_PLAYER_GESTURE_ONLY=1 UI_TEST_BROWSER=webkit npm --prefix web run test:ui
```

浏览器测试需要 Playwright 及对应浏览器。所有接口使用模拟数据，不控制真实音箱。

主要用例位于 [浏览器行为验证](../web/scripts/verify-ui.cjs)、[界面行为测试](../web/test/ui-behavior.test.mjs)、[弹框事件测试](../web/test/dialog-interactions.test.mjs)、[浏览缓存测试](../web/test/library-state.test.mjs) 和 [样式资源测试](../web/test/style-assets.test.mjs)。
